# PostgreSQL 数据库与迁移规范

## 1. 架构与连接配置

- **数据库引擎**：PostgreSQL 远程共享数据库，支持多工作站同时连接访问。
- **连接字符串注入**：`DATABASE_URL` 通过 `build.rs` 脚本在编译期从 `.env` 读取并嵌入二进制，确保生产环境中连接安全可配。
- **时区强制统一**：连接池建立时通过钩子统一设置会话时区为 `UTC+7`（Asia/Ho_Chi_Minh），对齐越南工厂业务时区。

## 2. 数据库设计三大铁律

1. **不定义 FOREIGN KEY 约束**
   - 业务表之间不建立物理数据库外键，表关联完全由 Rust 业务代码校验、数据库索引及业务状态机控制。
   - 目的：降低死锁概率，避免高频并发操作和级联删除引发的锁放大，保持数据迁移的轻量可控。
2. **金额统一 INTEGER 存储**
   - 所有单价、金额、成本统一使用最小货币单位（整型 `INTEGER` / `BIGINT`）存储：
     - VND：以 1 盾为最小单位（实际无小数位）
     - CNY / USD：以 1 分（0.01）为最小单位存储
   - 严禁在数据库中使用浮点数记录金额，前端和导出层统一负责格式化。
3. **并发更新必加行锁**
   - 在库存出入库、批次扣减、盘点过账等关键写路径上，必须使用 `FOR UPDATE` 显式加锁，配合数量约束条件避免负库存或超卖。

## 3. 自管理迁移机制

- **迁移目录**：`src-tauri/migrations/postgres/`。
- **当前状态**：包含 58 张业务表，22 个迁移版本（`001_init` 至 `022_remember_session_days`）。
- **启动并发互斥**：客户端启动时由 `run_migrations` 自动执行未完成迁移；执行前必须持有 PostgreSQL 会话级咨询锁 `pg_advisory_lock`，彻底防止多客户端并发启动时重复执行迁移。
- **事务隔离**：每一份 `.sql` 迁移脚本在独立的事务块中执行，保证迁移过程的原子性，失败自动回滚。

## 4. SQLx 查询开发约定

- **禁止字符串拼接**：所有 SQL 查询严禁任何形式的字符串格式化拼接，严防 SQL 注入风险。
- **静态查询**：确定语句统一使用 `sqlx::query!` 宏进行编译期类型与语法检查。
- **动态复杂条件**：报表与列表多条件筛选使用 `sqlx::QueryBuilder` 进行安全的参数化拼装。
